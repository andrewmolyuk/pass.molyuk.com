# Secret Relay — pass.molyuk.com

Однократный обмен секретом по ссылке + отдельно переданный PIN. Zero-knowledge сервер:
хранит только шифротекст, никогда не видит секрет, ключ шифрования или PIN. Полное ТЗ —
`secret-relay-spec.md`, крипто-прототип — `secret-relay-family.html`.

Стек: Cloudflare Workers + D1 (SQLite), статика отдаётся через Workers Assets. Домен —
корень `pass.molyuk.com`. RU/EN — переключатель на странице, автоопределение по
`navigator.language`, выбор сохраняется в `localStorage`.

## Разработка

```bash
npm install
npm run db:migrate:local   # применить миграции к локальной D1 (эмуляция в .wrangler/)
npm run dev                # wrangler dev, http://localhost:8787
```

## Деплой

```bash
npm run db:create          # один раз: создать D1-базу, вписать database_id в wrangler.jsonc
npm run db:migrate:remote   # применить миграции к реальной D1
npm run deploy
```

После `db:create` замените `REPLACE_WITH_REAL_DATABASE_ID` в `wrangler.jsonc` на `database_id`
из вывода команды.

Чтобы повесить на корень `pass.molyuk.com`, добавьте домен в Cloudflare Dashboard →
Workers & Pages → ваш воркер → Settings → Domains & Routes → Custom Domain (зона
`molyuk.com` должна быть уже на Cloudflare).

## Решения по спецификации (принято явно, не додумано по умолчанию)

**Race condition между GET и burn.** Спека прямо требует явного решения, не оставлять
как есть. Выбран вариант «приемлемый компромисс для семейного использования»: `GET
/api/secrets/:id` не удаляет запись, отдаёт данные многократно до истечения TTL или до
явного `burn`. Проверка PIN — чисто клиентская (AEAD), поэтому строгий `GETDEL` заставил
бы либо жечь запись до проверки PIN на клиенте, либо гонять PIN через сервер — оба хуже
для угрозы "случайная пересылка ссылки", которую спека объявляет целевой. Плюс это же
решение автоматически защищает от превьюшеров мессенджеров: превью — это только `GET`
без клика «Показать секрет», burn вызывается лишь после успешной расшифровки по клику
пользователя.

**История создания секретов владельцем.** Не реализована — по решению пользователя.
Сервер не хранит и не логирует факты создания сверх того, что нужно для работы (id,
шифротекст, TTL, счётчик попыток) — эти поля не привязаны к личности создателя.

**Топология деплоя.** Один Worker на корне `pass.molyuk.com` (не поддомен) — репозиторий
уже посвящён этому домену целиком, и `pass` семантически уже означает «секрет/пароль»,
так что отдельный `secret.pass.molyuk.com` был бы избыточен. Обратимо: перенос на
поддомен — это отдельная DNS-запись плюс передеплой, не миграция данных.

**D1 вместо Redis.** Спека предлагала Redis или self-hosted SQLite как варианты; при
деплое на Cloudflare естественный выбор — D1 (managed SQLite). Нет нативного `EXPIRE`
как в Redis — TTL проверяется в каждом запросе (`WHERE expires_at > now()`), плюс
почасовой Cron Trigger подчищает протухшие записи и старые записи rate-limit лога,
чтобы таблицы не росли бесконечно.

**Rate limit на `attempt-failed`.** Реализован в самой D1 (таблица `attempt_failed_log`,
скользящее окно 60 секунд, 20 попыток на IP) — без отдельного KV/Durable Object, чтобы не
плодить сущности ради семейного масштаба трафика.
